# Core exports, worker protocol and execution ownership

C09-01–04 and C10-05, 10 November 2026. The
[maintained inventory](boundaries.json) is generated by
`python3 rust/tools/boundary_inventory.py --output REPORT.json`. It covers every
public root module, its direct declarations/reexports, static Rust use-tree and
qualified-path consumers, Python worker request sites and dynamic adapters, and
native compile/live/restore/search representation consumers. It is a conservative
source inventory, not a compiler-resolved whole-program graph or proof of absence.
No unmatched textual caller permits removing a public item or diagnostic.

## Consumer and API decisions

| Consumer | Boundary / retained dependencies | Decision |
| --- | --- | --- |
| Game service, persistence, replay, shares, votes, presence and Lab adapter | Authoritative `api` types and `recommend_bot`; codec/geometry for explicit serialized/spatial work | Maintained service imports now use the facade; bot policy calls the supported bounded recommendation entry point. Auth, revision checks and durable publication remain adapter responsibilities. |
| JSON-lines worker and its search/sequence helpers | Explicit `api::experimental_search` imports; codec/data/geometry/diagnostics for offline tooling | Experimental exports list the exact currently needed arena/search/session types; no wildcard reexport/new crate. Old module paths remain valid aliases. Session layout is not promoted to a stable contract. |
| Native tests, dense reference diagnostics and restore scans | Broad modules, `NativeSession`, objects/bindings and session internals | Retain visibility until full unique coverage/caller migration is proved. Tests are consumers, including currently ignored/full-feature ones. |
| Python oracle/arena/search tools | Versioned `Worker.request`, original wire operations and runtime/source identities | Retain all operations and pinned source policy. Direct literal request/stream sites are attached to each operation; manual/indirect consumers remain explicit. |
| Rust embedding example and facade | `api::{GameContent, LiveGame, PlayerCommand, ExecutionBudget}` | Authoritative facade is intended pre-1.0. Search recommendation accepts a scoped authenticated hero and budget, does not commit, and retains legal deadline fallback/cancellation. |

The inventory also records public reexports and experimental modules that a
simple `use goa2_core::interpreter` search would miss after adapter migration.
Internal relative imports, implementation methods, conditional tests and external
embedders are not evidence-free deletion candidates. No arena slot/compiler/import
or profiling structure is made private in this batch. Their future restriction
requires complete migration and C04 full/restore evidence. A new crate has no
additional consumer/build-boundary justification here; retain the current crates.
This closes API refinement and maintained adapter migration without silently
turning the experimental session implementation into a supported representation.

## Worker operations and dynamic dispatch

All **39** retained operations have status, owner role, consumer/retirement policy,
[protocol examples](../worker-protocol-examples.json), schema and error-test links
in [worker operations](../worker-operations.json). The schema-only examples are
synthetic: an empty envelope demonstrates required JSON shape, not valid native
rules execution. Native tests deserialize every example, reject missing required
fields and reject future worker versions before execution. Tooling ensures a new
or removed enum variant cannot be omitted from the examples/status inventory.
Unit-variant extra-field tolerance stays unchanged; structured operations retain
strict field validation. No wire packet fields, correlation IDs or error strings
are deliberately changed by the import/version cleanup.

The persistent-process check is:

```sh
python3 rust/tools/worker_contracts.py --binary /absolute/path/goa2-search-cli
```

It checks malformed JSON, unknown operations, future schemas and 64 invalid
structured requests, then verifies a full-width ID and successful capabilities
request in the same process: **71 packets, 69 rejections, two final successes**.
It does not run unavailable corpus-backed workloads or certify their gameplay.

Three worker-related variable request sites require retention: arena calibration
reads an explicit case's operation; arena matches choose the search operation by
phase/policy; the calibration test subclass forwards that operation. The streamed `operation_records` adapters for `arena_replay` and
`stack_trace_stream` are included alongside ordinary requests. The common
`oracle.py::Worker.request` builds/writes the packet and validates version/id/error
shape under its watchdog. `self.http.request` in the staging verifier is separately
marked as HTTP, not worker dispatch. These dynamic paths are recorded, not assumed
absent because a literal request search missed them. Existing manual consumers for
operations without direct literal sites remain retained pending migration.

Diagnostic operations still dispatch to the separate core `diagnostics` module;
search orchestration stays in worker helpers. `validate_execution` intentionally
rejects the old codec-only transition path. No capability or porting operation is
deprecated/removed without moving callers and preserving unique tests.

## Internal diagnostics without a wire migration

`goa2_core::diagnostic` supplies stable category codes by `EngineError` variant:
`unsupported`, `invalid_input`, `rule`, `cancelled`, `deadline`, `step_limit`, plus
adapter-owned `internal`. A `Diagnostic` carries only category and a bounded
boundary enum; it never copies arbitrary private payloads or error strings.
Service errors retain the category/context for logs and preserve the existing
HTTP status, `detail` field and `Display` text, including Lab/export consumers.
Internal/storage failures keep their generic public detail. Worker error packets
remain the original strings and JSON shape; Python's unsupported-prefix handling
therefore continues to work. Category tests check every engine variant and safe
context; an actual Axum response-body test protects the old packet shape.

## Dense versus object-aware execution (C10-05)

| Caller family | Selection and unique coverage | Retain/migration requirement |
| --- | --- | --- |
| Authoritative live games, bots, checkpoints and private replay | Setup/import produces admitted object bindings; `NativeSession::compile` validates the envelope and chooses object-aware execution when bindings are present | Preserve physical aliases, scope/continuation state, rollback and request high-water identities. No flattening to dense rows. |
| Canonical stack/diagnostic worker traces | Empty binding sets still choose dense execution; stack/request semantics and old codec diagnostics have retained callers | Keep canonical input and every distinct instruction/restore branch until independently migrated. |
| Object execution/arena, complete games and streamed replay | Nonempty bindings compile the shared-object implementation or reject unsupported families; both streamed state and ordered event/request records are consumed | Full external corpora and exhaustive restore evidence are required before retiring any branch. |
| Search, greedy, planning, rollout, arena/offline policies | Use private session clones and existing representation-selected methods; state fingerprints remain process/search-local | Preserve alias isolation, tie breaks/RNG, budget/node/fallback behavior and matched fixed-work evidence before representation migration. |
| Native restore/instruction/property tests | Both dense and object-aware branches, named smoke cases and full-feature/ignored gates | Unavailable inputs do not make their consumers or unique coverage obsolete. |

The machine list records every selected source containing the relevant compile,
restore, live/search or representation entrypoints. Selection is based on admitted
state/bindings, not filename or whether the caller is Python. No dense execution,
plain/gzip reader, public alias or fixture family is retired. C10 structural work
and full performance/differential acceptance remain separate gates.
